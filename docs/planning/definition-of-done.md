# Definition of Done

## Engineering issue

- Scope is one independently understandable outcome mapped to an approved requirement/story.
- Dependencies are satisfied; no hidden architecture decision is introduced.
- Builder implements against approved contracts and ownership boundaries.
- Acceptance criteria pass; QA records independent verification, including relevant negative/boundary cases.
- Security, privacy, rights, accessibility, failure and operational implications are addressed where applicable.
- Required automated checks pass and commands/results are recorded. Never claim tests ran unless they did.
- Documentation and repository decisions are updated; behavior/API/data changes are documented.
- PR review is complete with no blocking comments.
- Deployment, migration, rollback and monitoring evidence exists when affected.

## Planning/research issue

Deliverable exists in repository with sources, dates, confidence, owner and approval status. Facts, hypotheses, decisions and unknowns are distinct; acceptance is measurable; handoffs to Architect, Builder, QA or DevOps are explicit.

## Release

Product must approve scope; DevOps/QA/Security provide measurable gates. Evidence covers approved journey, rights/data correctness, security/privacy, SLO/recovery, observability/runbooks, support ownership, deployment/rollback and sign-offs. No gate passes without recorded evidence.

## Status discipline

Activity, code presence or issue description is not completion evidence. Record evidence links and verifier/date. Never infer completion from intent or this draft roadmap.
